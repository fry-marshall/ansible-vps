# Ansible VPS — Setup GUI

A local web interface to securely configure a fresh VPS from scratch using Ansible — no terminal required for the setup process.

**Stack:** Angular 19 · Node.js/Express · Socket.IO · Ansible

---

## What it does

The GUI walks you through a step-by-step wizard to:

1. **Test SSH access** as root on your fresh VPS
2. **Change the root password** (handles first-login forced password change)
3. **Copy your SSH key** to the server
4. **Save deployment config** (deploy user, custom SSH port, key path)
5. **Run the Ansible playbook** with real-time logs

Once deployed, the Ansible `secure-server` role automatically:

- Creates a non-root `deploy` user with sudo access
- Moves SSH to a non-standard port (default `1024`)
- Disables root login and password authentication
- Sets up UFW firewall (SSH + 80 + 443)
- Installs and configures Fail2ban
- Installs Docker & Docker Compose
- Configures unattended security upgrades
- Sends email alerts on SSH login (via SMTP/Gmail)

## Installation

```bash
git clone https://github.com/your-username/ansible-vps.git
cd ansible-vps
```

### 1. Configure Ansible variables

Copy the example files and fill in your values:

```bash
cp ansible/group_vars/vps/vars.yml.example ansible/group_vars/vps/vars.yml
cp ansible/group_vars/vps/vault.yml.example ansible/group_vars/vps/vault.yml
```

Edit `ansible/group_vars/vps/vars.yml` — adjust `deploy_user`, `ssh_port`, `allowed_ports` if needed.
> The `deploy_user_pubkey` field is **written automatically by the GUI**, you don't need to set it manually.

Edit `ansible/group_vars/vps/vault.yml` with your SMTP credentials:

```yaml
vault_smtp_user: your@gmail.com
vault_smtp_password: your_gmail_app_password   # use a Gmail App Password
vault_alert_email: your@gmail.com
```

> **Optional but recommended:** encrypt the vault file so it's never stored in plaintext:
> ```bash
> ansible-vault encrypt ansible/group_vars/vps/vault.yml
> ```
> You'll need to enter this vault password in the GUI before deploying.

### 2. Start the GUI

```bash
./start.sh
```

This will:
- Install npm dependencies automatically if missing
- Start the backend on `http://localhost:3001`
- Start the frontend on `http://localhost:4200`

Then open **http://localhost:4200** in your browser.

## Usage

### First-time setup (wizard)

1. Click **"Configurer mon premier VPS"**
2. Enter your VPS IP and root SSH port (usually `22`)
3. Follow the wizard steps — the GUI tests each step before moving on
4. At step 5, click **"Lancer le déploiement"** — Ansible runs and streams logs in real time
5. Once successful, the host is marked as **configured** and saved locally

### Re-deploying

Go to the **Deploy** page, select your tags (or run the full playbook), enter your vault password if encrypted, and click **Deploy**.

## Security notes

The following files are **gitignored** and must never be committed:

| File | Why |
|------|-----|
| `ansible/group_vars/vps/vault.yml` | Contains SMTP credentials |
| `ansible/group_vars/vps/vars.yml` | Contains your SSH public key and server config |
| `ansible/inventory.ini` | Auto-generated, contains your VPS IP |
| `gui/backend/data/` | Contains host state (IP, ports, deploy timestamps) |

> If you forked this repo and these files are already tracked in your git history, untrack them:
> ```bash
> git rm --cached ansible/group_vars/vps/vars.yml
> git rm --cached ansible/inventory.ini
> git commit -m "chore: remove sensitive files from tracking"
> ```

## Resetting a host

If your VPS was reinstalled and Ansible needs to run again from scratch:

1. Open `gui/backend/data/hosts.json`
2. Set `"status": "key-copied"` and remove the `lastDeployAt` field for that host
3. Restart the backend — the inventory will be regenerated using `root@22`

Or delete the host from the dashboard and re-run the wizard.
